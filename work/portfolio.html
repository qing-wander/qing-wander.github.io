问题

求职时作品散落在 PDF、GitHub、聊天截图里。HR 三分钟只能看到「做过什么」，看不到「怎么想、怎么解决」；面试官想深挖时，又得反复追问细节。

方案

把个人履历做成一套内容系统：一份 JSON 是唯一真相源，脚本生成首页、简历、作品案例与 RAG 知识库；用校验脚本与 CI 守住页数、结构与事实一致性。

结果

站点持续迭代 3 个月：简历稳定在 2 页、改内容不改代码、问答与留言都有后台可观测。所有页面可离线静态托管，回滚即换一个提交。

02

产品定位

POSITIONING

一个页面该不该有某个功能，先看它服务谁，再看它是否值得维护。

为谁做

招聘方（HR 初筛 3 分钟 / 面试官深挖 10 分钟）与同行（想看实现细节的人）。

明确不做

  • 不做博客 CMS：内容量级不需要，也不该为了「看起来像产品」引入编辑器
  • 不做多人协作：单作者、低频更新，权限体系是纯成本
  • 不做营销落地页：目标是让人看懂，而不是让人下单

为什么这样取舍：单用户、低频更新、强格式约束 —— 这三个条件决定了「静态优先、生成式维护」是唯一划算的架构。

03

整体架构

ARCHITECTURE

五层，每层只做一件事。上面两层是内容与生成，中间一层是门禁，下面两层负责交付与运行时能力。

04

技术选型

STACK & TRADE-OFFS

每个选择都写清代价；没有代价的技术选型，通常意味着没想过。

选择为什么放弃了什么
原生 HTML / CSS / JS，无框架站点只有三个页面类型（长首页、简历、案例页），交互集中在少数模块。引入框架会让构建链、依赖升级和调试面同时变大，收益为负。React / Vue / 各类静态站生成器
数据驱动生成，而不是手写 HTML同一份履历要同时出现在首页卡片、简历正文、案例页与问答知识库里。手写会立刻产生四份互相漂移的副本。复制粘贴多份 HTML、在线 CMS
静态优先，仅问答 / 留言走 Functions只有三件事需要写库：留言、问答埋点、后台配置。其余全部可以预生成，静态托管的成本与回滚速度都优于任何动态方案。全站 SSR、全站上 KV / D1
字符 bigram TF-IDF 做检索36 个切片量级下，embedding 的收益抵不上费用与不可解释性；bigram 检索可以离线复现、能说清「为什么召回这一段」。向量数据库、在线 embedding 服务
用设备哈希做留言隔离网页拿不到硬件 ID，也不该长期持有可识别信息。前端生成随机 ID、后端加盐哈希，只存不可逆值。手机号登录、浏览器指纹

07

难题档案

PROBLEM FILES

三个真正卡住过进度的问题：现象、怎么定位、最后怎么解决、留下了什么。

ISSUE-01

简历越写越长，2 页红线守不住

SYMPTOM · 症状

每加一段经历就手动数页，临界状态下字号、行距的微小改动会让 PDF 从 2 页跳到 3 页。

DIAGNOSIS · 诊断

字数不是页数的可靠代理；靠肉眼检查，等于把门禁放在上线之后。

FIX · 处置

正文加 3800 字预警；用无头 Chrome 真实渲染统计页数，纳入 CI；简历内容只从 JSON 生成，避免手工改动绕过检查。

RESULT · 结果

从「改完再看」变成「提交前就知道」，2 页稳定，改版不再心惊。

ISSUE-02

主站和接口不在一个域

SYMPTOM · 症状

主站部署在纯静态托管，接口在另一个域。后台设置的主题、问答、留言在部分入口上静默失败，页面看起来「没反应」。

DIAGNOSIS · 诊断

相对路径请求打到了没有接口的静态域名；接口站又没有开放跨域，失败被 catch 吞掉，问题不会报错只会消失。

FIX · 处置

统一一套线路规则：静态域名优先转向接口域名，逐个尝试、只认 JSON；接口侧对只读配置开放跨域。任何一步失败都自动降级，不影响页面可用。

RESULT · 结果

主题、问答、留言共用同一套线路规则，单点故障不再导致整块功能消失。

ISSUE-03

3D 素材撞上部署上限

SYMPTOM · 症状

某次部署直接构建失败，本地一切正常，线上没有新版本。

DIAGNOSIS · 诊断

原始 3D 素材（数百 MB）进了仓库，超过静态托管平台的单文件上限；构建日志在最后一步才报错。

FIX · 处置

把原始素材归档到云盘并移出仓库，仓库只保留运行时真正加载的压缩模型；补上构建体积的检查意识。

RESULT · 结果

构建恢复、仓库可正常克隆，线上取景效果完全不变。

09

亮点

WHY IT WORKS
01

单一真相源

一份履历 JSON 驱动首页、简历、案例页、知识库四个消费端，改一处不会漏三处。

02

生成物不手改

所有 HTML 由脚本产出，CI 检查漂移；想改样式就改模板，想改内容就改数据。

03

约束即设计

2 页、无框架、零运行时依赖这些限制，最后变成了页面的识别度，而不是妥协。

04

可观测的闭环

问答埋点回流后台，问题聚类后发现空召回话题，再回头补知识切片 —— 数据驱动内容。

05

渐进增强

关掉 JS 仍能读完页面，打印就有正式排版，分享出去的链接自带摘要卡。

11

复盘沉淀

RETROSPECTIVE
求职站不该是作品的照片墙，而该是一次可以被验证的思考过程。

LEARNED · 学到了什么

  1. 先定约束，再写内容：页数、依赖、部署方式想清楚后，后面每个选择都变简单。
  2. 把校验前移：能写成脚本的检查，就不要留给肉眼。
  3. 数据与呈现分离：改内容不该碰代码，改样式不该碰事实。
  4. 失败要吵：静默的 catch 比报错更危险，降级策略必须可见。

REUSABLE · 沉淀下的资产

  1. 数据 → 模板 → 生成 → 校验 → CI 的骨架，可直接套到任何个人站
  2. 无头浏览器量页的校验脚本（印刷类交付通用）
  3. 设备隔离留言与静态 RAG 的两套最小实现

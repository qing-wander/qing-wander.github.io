## 0. 一句话结论

这个仓库已经从「一个静态简历页」长成了**一个招聘方真的能用的决策工具**：

> 招聘方粘一段 JD 进来，8 秒后拿到一张表——每条要求落在哪段经历、缺口在哪、面试该顺着问什么。

支撑这张表的是四件套闭环：**知道答什么（RAG）→ 长什么样（9 款角色皮肤）→ 怎么说（浏览器 + 云端双通道语音）→ 能不能胜任（JD 匹配）**，全部跑在 0 元预算、无常驻服务器、无框架、无构建的前提下。

所以「把这些功能做完」的收获不是「我会做网页」，而是三句更硬的话：

1. **我能把一个 AI 能力做成别人敢用的产品**（有边界、有限流、有降级、有验收）。
2. **我能一个人跑完「调研 → 选型 → 实现 → 上线 → 验收 → 复盘」全链路**（七份设计文档 + 一份 TODO 台账就是痕迹）。
3. **我留下的不是一堆代码，是一套可迁移的工程范式**（下面第 4、5 节）。

### 2.3 L3 前端交互（`js/main.js` 12 节 + 视口自适应）

移动端菜单 / 导航高亮 / 滚动进场 / 数字滚动 / 技能条 / 项目模态框 / Toast / 风格控制台彩蛋 / 分享卡 / AI 面板 / 留言墙 / 视口自适应。

三个值得单独拎出来的：

1. **顶栏导航「逐项退让」**（最新一次提交）：不写死断点，而是以右侧「分享 / 访问统计」区的左边界为极限，从最右一项开始隐藏被遮住的导航项，一项都放不下才整体收成汉堡菜单。**字体放大、浏览器缩放、翻译变长都走同一套几何判断**，永远不会横向裁切。裁决前先复位 `.bar-tight` 与隐藏标记，避免上一轮结果污染下一轮导致抖动。
2. **`--vw-real`**：用 `documentElement.clientWidth` 修正 Windows 经典滚动条占宽，让全幅区块不被撑出横向滚动条。
3. **ES5 + IIFE + 无框架**：不是复古，是约束——`file://` 直开、老浏览器、无构建、单文件可读；代价是手写渲染层与事件绑定，收益是零依赖、零供应链风险。

**为什么这四件是「一套」而不是四个功能**：

## 4. 把这些功能做完，收获什么

### 4.1 对外：招聘方的「三分钟闭环」

求职最大的问题不是「我没做过」，而是**别人没时间信**。这个站把「信」的成本压到了三次点击：

| 时间 | 招聘方动作 | 站内响应 |
|---|---|---|
| 0–30 秒 | 打开主页 | 姓名、定位、量化战绩、三个项目结论 |
| 30 秒–2 分钟 | 点 AI 助手问「他做过 Agent 吗」 | 检索 37 段切片后作答，标出依据；答不出说「记录里没有」 |
| 2–3 分钟 | 粘一段在招 JD | 8 秒出对照表：覆盖 / 部分 / 缺口 + 证据出处 + 追问点 |

**JD 匹配这一步是分水岭**：它把「作品集 = 展示」变成「作品集 = 决策工具」。招聘方不需要替你做判断，站内 Agent 已经替他把「岗位要求 ↔ 候选人证据」对齐了——而且**敢列缺口**（无证据的 `covered` 自动降级为 `partial`，`src` 认不出就丢弃），这比一张满分表更可信。

**注意一个刻意的例外**：CareerAgent（W-02）不做网页 demo。它是本地优先的桌面应用，数据只存本机、跨设备走恢复码 E2EE 同步，Lighthouse 上只有 `/v1` 同步哑管道（`/v1/health` → `200`，根路径返回 `{"error":"未知协议路径"}`）。
它的验证链是「**落地页 → 下载安装 → 真跑一次同步**」，不是「浏览器里点两下」。公开 web demo 会直接推翻「数据不出本机」这条卖点——这是产品边界，不是能力缺口。

## 5. 经验沉淀（33 条「踩过才知道」）

> 每条都给「结论 + 证据」。功能会过时，判断不会。

### 5.1 架构与选型（6 条）

1. **先测可达性，再写代码。** 境内 `workers.dev` / `vercel.app` 超时、CloudBase 可用 → 决定「检索下沉 + 境内主通道 + 边缘备线」。（`ai-assistant-survey.md` §3）
2. **能力下沉，密钥不上前端。** 检索与模型调用全在函数端；前端只发问题。这条一破例，后面所有安全设计都白做。
3. **新功能优先寄生，不新建后端。** JD、TTS 都是同一台云函数的 `mode` 分支——白名单、限流、日志、脱敏全部免费继承。（`jd-match.md` D-J1）
4. **单一真源 + 派生快照 + 双向校验。** 派生必须能被 `--check` 抓回源；没有校验的派生，迟早漂移。
5. **派生产物必须进 CI，并带隐私闸门。** 改 JSON 忘了重建 → 页面静默用旧数据，AI 会在面试官面前念错你的经历。（`.github/workflows/build-kb.yml`）
6. **无常驻后端 = 状态放 KV，但要接受它不是数据库。** KV 无事务，读改写会丢；要严格不丢就上 Durable Objects。选它，就得知道边界。

### 5.2 模型输出工程（6 条）

7. **输出必须两层约束。** 第一层 prompt 写死 schema 与判定口径；第二层服务端白名单收紧（分数夹取、枚举校验、长度截断、行数上限）。
8. **宁缺毋滥：证据认不出就丢弃。** `src` 必须原样取自上下文切片 id；`covered` 没有证据自动降为 `partial`。（`jd-match.md` D-J4）
9. **解析失败整次拒绝，不给半截表。** 半截对照表比失败更误导，前端引导重试即可。（D-J7）
10. **拆分再检索，别用整段长文本单查询。** 多主题 JD 会被最长主题主导；逐条召回 + 合并加权更均衡。（D-J2/D-J3）
11. **按内容类型加权，而不是按相关度一把梭。** 对照表要「可验证的证据」，项目/经历 1.0、联系 0.1。
12. **相似度只做提示，不做筛选。** `ground`（证据与原文重合度）只用于前端 hover，避免把合理转述误判成幻觉。

### 5.3 安全与隐私（6 条）

13. **限流只有「放行才自增」才对。** 早期版本被拒后仍 bump 并刷新 TTL → 访客被永久锁死；这是本地测不出来的上线 bug。
14. **注入检查放在扣额之前。** 被拦截的恶意请求不该占用访客当天次数。（D-J6）
15. **JD 不套用敏感词拦截。** 「薪资 / 外包 / 到岗」是 JD 的正常内容，按敏感词杀会全误杀；只拦提示注入。（D-J5）
16. **比较 token 用常量时间。** 成本近乎为零，没有理由不做。
17. **隐私靠「白名单 + 全量断言」，不靠记性。** `blocked_fields` 生成期拦截 + CI grep 手机号，双保险。（`build-kb.yml`）
18. **日志要能公开，所以只存哈希。** IP 用盐化哈希；JD 只存脱敏后前 300 字摘要，不存完整原文；TTL 30 天自动清理。

### 5.4 前端与浏览器（6 条）

19. **自动播放绕不过，就做成状态机。** 先尝试播 → 420 ms 没出声显示引导 → 1.2 s 看门狗兜底；`unlock()` 必须**同步**在 tap 回调里（iOS 手势过期）。
20. **判断成功看 `onstart`，不看 `speaking`。** 被拦截时 `onerror` 不一定抛。
21. **Chrome 约 15 秒静默截断** → 按标点分句（≤110 字）+ 链式 `onstart/onend` + 持有 utterance 引用防 GC + 每段看门狗。
22. **`getVoices()` 异步且不完整** → 监听 `voiceschanged` + 3 s 兜底 + **过滤 name/lang 含 `undefined` 的残缺条目**。
23. **`loadVoices()` 与 `syncUI()` 会互相递归。** 音色列表为空时无限递归 → IIFE 整体中断，连 `window.AIVoice` 都挂不上；本地 mock 恒有中文音色所以从未暴露，是生产域名验收抓到的。修法：`voicesBusy` 重入保护，且 UI 同步必须在保护区内调用。
24. **导航不要写死断点，要几何测量。** 以右侧区域左边界为极限逐项隐藏，字体放大 / 缩放 / 翻译变长全走同一套判断；裁决前先复位，避免抖动。

### 5.5 云函数与部署（5 条）

25. **控制台「上传代码」弹系统文件框，自动化喂不进去；在线编辑器是 Hello World 模板，点部署会覆盖线上。** 最终走 SCF 云 API 打包上传，并保留一份 `git HEAD` 作回滚包。
26. **TC3 签名不能把运行角色临时密钥和子账号永久密钥混用。** SCF 注入 `TENCENTCLOUD_SESSIONTOKEN`，混用会 `AuthFailure.TokenFailure`；`tts.js` 因此改成「两套密钥成套取用」。
27. **用云 API 改函数配置必须全量回传环境变量。** 漏掉 `AI_API_KEY`，`/chat` 立刻失效；控制台 UI 编辑会自动保留，API 不会。
28. **环境变量会覆盖代码默认值。** 函数代码已支持 `*.shenge-work.pages.dev`，但线上 `ALLOWED_ORIGINS` 是精确列表 → 预览域一直 403。不是代码 bug，是配置没跟上。
29. **部署完必须验证三件事。** 线上首页与本地字节级 diff、接口实测、控制台零错误；「部署成功」不等于「可用」。

### 5.6 内容、文档与协作（4 条）

30. **内容不更新的根因不是懒，是贵。** 改一个 JSON + CI 重建，比改三个文件再记得同步便宜一个数量级。
31. **删内容要全链路删。** JSON + `resume.html` + 快照 + 知识库 + README，最后 `grep` 全仓零残留 + `--check` 双校验。漏一处，AI 就会念出你已删掉的公司。
32. **文档也会漂移，而且比代码更隐蔽。** README 说「push 不触发构建」，实际 3 秒就构建；这种矛盾比「没有文档」更伤信任。**冲突时以代码与实测为准，并立刻改文档。**
33. **「缺口」要区分能力缺口与产品边界。** 把 W-02 写成「缺个 web demo」就是典型错位：本地优先产品做公开 demo，等于亲手拆掉自己的卖点。**边界要写成「已决策不做 + 理由」，否则三个月后会被自己当 bug 修掉。**（本站对照：T9 本地推理「已决策不做」也是同类。）

> 附：git 相关的两条也值得记 —— ① 本机 `git fetch` 报 `Empty reply from server` 不是代理不通，是代理对 HTTP/2 处理有问题，加 `-c http.version=HTTP/1.1` 即好，push 还需 `http.sslBackend=openssl`；② **`git reset --hard` 会抹掉未上线的工作**，对齐 refs 要用 `--mixed`。（`TODO.md` §3.2）

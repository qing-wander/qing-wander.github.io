## 1. 已确认问题清单

### P1-1 / T27 · AI 数字分身问答：模型生成链路故障，全部降级兜底

- **严重度**：高（核心功能不可用；JD 匹配不依赖模型，不受影响）
- **复现步骤**：
  1. 浏览器打开 https://chenpeisheng.cn/ ，右下角打开数字分身面板；
  2. 提问「你的技术栈和主要经历是什么？」；
  3. 接口 `POST /api/chat` 返回 HTTP 200，但 `answer` 为固定兜底文案。
- **接口实测**（`POST /api/chat`，`{"q":"你好"}` / `{"q":"你的技术栈和主要经历是什么？"}`）：
  ```json
  {
    "ok": true,
    "answer": "这条我暂时答不上来（模型服务不可用），你可以直接看页面上的原文。",
    "citations": [ { "id": "me-01", "title": "陈培胜 · AI Agent 工程师 / AI 应用开发工程师", ... } ]
  }
  ```
- **现象判定**：检索层（D1 FTS5 + Vectorize）正常命中 citations；故障出在生成环节。对照
  `functions/api/chat.js` 的 `callWorker()`：返回 `ok:false`，原响应体不回传失败 reason。
- **可能根因**（部署后按 `failReason` 对号入座）：
  - `no-worker`：Pages 环境变量 `KB_WORKER_URL` / `KB_TOKEN` 缺失或被清空（对照近期邮件密钥同批
    清空事故）；
  - `worker-http`：Worker `resume-kb-api` 不可达 / 非 200；
  - `worker-bad` / `empty-text` / `ai-run-failed`：Worker 内 Workers AI 模型调用失败（配额、模型名、绑定）。
- **本轮修复**：见顶部「已落地代码改动」。Worker 地址 `https://resume-kb-api.shenge-work.workers.dev`
  （本机直连被境内 DNS 污染 / 超时，不代表 Worker 离线；Pages Function 走边缘内网调用）。
- **影响**：访客任何问答都只能拿到兜底话术；qa_logs 原记录的 answer 也是兜底文案，问答看板的
  召回 / 质量分析会失真。
- **验收**：普通问题返回真人风格回答；响应不出现 `degraded:true`；qa_logs 正常记模型名。

### P1-2 / T28 · Cloudflare Turnstile 报错 110200，留言墙人机校验未生效

- **严重度**：高（安全 / 反刷防线失效；按设计 fail-open，留言仍可提交，但降到严格额度档）
- **复现步骤**：
  1. 打开首页 `#wall` 留言墙区域；
  2. 控制台持续刷出：
     - `[Cloudflare Turnstile] Error: 110200.`
     - `Failed to execute 'postMessage' on 'DOMWindow': The target origin provided ('https://challenges.cloudflare.com') does not match the recipient window's origin ('https://chenpeisheng.cn').`
  3. DOM 检查：`.wall-turnstile` 容器内只有空 `<div>` 和隐藏的 `cf-turnstile-response` input，
     **没有 challenge iframe**；`document.querySelectorAll('iframe')` 为空；
  4. 网络面板：`challenges.cloudflare.com/.../failure_retry/...` 反复重试，长期 `inflight`。
- **配置现状**：sitekey `0x4AAAAAAGHnx0m992aGGpUJ`（`js/main.js` `TS_SITEKEY`）。
- **110200 常见根因**：sitekey 与当前域名不匹配 / 该 sitekey 在 Cloudflare 后台未把 `chenpeisheng.cn`
  （及备用 `*.pages.dev`）加入托管域名 / widget 配置或站点未激活。
- **代码侧核对**：前端 sitekey 与服务端 `TURNSTILE_SECRET`（`functions/api/wall.js`）配对逻辑正常；
  110200 是前端站点校验阶段错误，根因在 Cloudflare 后台，代码改不了。
- **影响**：`tsToken` 永远为空，前端走 `error-callback` 隐藏容器；服务端收不到有效 token，自动降到
  「每 IP 每小时 1 条」严格额度，人机校验这道闸实际没起到作用。
- **待办**：CF 控制台 → Turnstile → 该 sitekey，核对域名列表；widget 类型与前端 `size:'normal'` 一致；
  核对 `TURNSTILE_SECRET` 与 sitekey 同属一个站点。
- **验收**：widget 渲染出 checkbox / challenge，提交时 `cf-turnstile-response` 非空；控制台无 110200。

### P2-1 / T29 · Cloudflare Web Analytics beacon 被 CSP 拦截，统计这一路未生效

- **严重度**：中（可观测双路之一缺失；不影响页面功能）
- **现象**：控制台 error
  > `Loading the script 'https://static.cloudflareinsights.com/beacon.min.js/vce701823e78c4301a35b7e07294d87301792088814092' violates the following Content Security Policy directive: "script-src 'self' 'unsafe-inline'". Note that 'script-src-elem' was not explicitly set...`
- **对照**：Clarity（`k.clarity.ms/collect`）与 Umami（`gateway.umami.is/api/send`）上报均 200；只有
  CF beacon 被挡。beacon token 已配置（`js/analytics.js` `cfBeaconToken: e8d13ee2...`），脚本由
  `loadCloudflareBeacon()` 动态注入。
- **排查结论**：仓库 `_middleware.js` 对公开站只下发 `Content-Security-Policy: frame-ancestors 'self'`，
  HTML 中也没有 CSP `<meta>`；线上首页响应头实测同样只有 `frame-ancestors 'self'`。报错里的
  `script-src 'self' 'unsafe-inline'` 不在仓库代码，疑来自 **Cloudflare 面板的安全头规则**，或浏览器扩展。
- **待办**：真机无扩展环境 DevTools 核对首页响应头第二条 CSP；若在面板，`script-src` 放行
  `https://static.cloudflareinsights.com`，`connect-src` 放行上报域名；若不打算用 CF Web Analytics，
  留空 `cfBeaconToken` 即可消除报错。

### P3-2 / T30 · 头像 PNG 体积偏大（性能提醒，非功能故障）

- **实测**：`images/avatar-male.png` 2.36MB、`images/avatar-female.png` 2.56MB，均 1536×1536；
  展示位头像最大约 420px（Retina 840px 足够）。
- **引用核查**：`avatar-male.png` 除 `asset-manifest.json` / `asset-map.js` 外前端零引用，疑似死资源；
  `avatar-female.png` 被 `js/gender-switch.js` 女版头像引用；男版默认头像用 `portrait.jpg`（264KB）。
- **建议**：先确认 male 是否后台 / 分享卡残留引用，无引用则归档移除；female 派生 840×840 WebP
  （或优化 PNG），同步 manifest / asset-map 与 COS 远端副本。并入 T25 性能专项。
